## 1. 決定：締切は 9/30 のまま。ただし公募の性格を変える

66日で新作は撮れない。しかし応募要件は「2025年10月以降に完成した作品」＝**すでにある作品で応募できる**。

したがって第2回は「新作コンペ」ではなく、
**「この1年に九州で生まれた短編の棚卸し」**として告知する。

- 締切延長はしない（延長は告知力の弱さを露呈し、締切の重みを失わせる）
- **コピーの主軸を「今から撮ろう」から「もう撮ってある、その一本を」に振る**
- 新作狙いは第3回から（第3回は3月に要項公開・6月公募開始を厳守）

これが今回いちばん大きな方針転換。サイト・SNS・DMの文言をすべてこの軸に合わせる。

## 2. 確定：2026年12月12日（土）18:00〜21:00 ／ 電気館

**確定済み（2026-07-26）。** 3時間・夜枠。ここから全体を逆算する。

この枠が持つ意味：

- **3時間しかない** → 上映本数の上限が厳しく決まる（→ §3）
- **夜・土曜** → 客層が家族連れから「仕事帰りの大人・学生」に変わる。告知の絵と文言をそれに合わせる
- **21:00 完全退館** → 押した時の逃げ場がない。運営設計にバッファを組み込む（→ §3 タイムテーブル）

**要確認（電気館へ）：**
1. 18:00 は「開場」か「開演」か。スタッフの搬入・準備は17:30から入れるか
2. 客席数（動員目標150人が枠内か）

## 3. 確定：上映6本（合計95分以内）／ 目標応募25本

3時間枠から逆算すると、**前提だった「7〜8本」は入らない。6本が上限。**

### タイムテーブル（骨格）

| 時刻 | 内容 | 分 |
|---|---|---|
| 18:00 | 開場・受付（**観客賞の投票用紙をここで配る**） | 15 |
| 18:15 | 開会挨拶・趣旨説明 | 10 |
| 18:25 | **上映ブロックA（3本）** | 65 |
| 19:30 | 休憩 | 10 |
| 19:40 | **上映ブロックB（3本）** ／ 終了時点で投票締切 | 40 |
| 20:20 | 監督クロストーク（登壇監督まとめて1回）※**裏で観客賞を集計** | 20 |
| 20:40 | 授賞式・閉会 | 20 |
| 21:00 | 終了・退館 | |

→ 上映に使えるのは **105分**。作品間の転換を6回×1.5分＝9分見て、**純上映96分**。

### 決定事項

- **上映6本 ／ 合計上映尺 95分以内**（平均16分）。尺は5〜25分と幅があるので「本数」ではなく**合計尺で組む**。短編が揃えば7本も可（例：10分×7＝70分）
- 監督トークは各作品ごとではなく**最後にまとめて1回**。3時間枠では個別トークは物理的に不可能
- **観客賞の集計時間をクロストークで吸収する**（この配置が唯一の解。集計のために進行を止めない）
- **司会に「休憩を10分→5分に縮める権限」を渡す。**押した時の吸収弁がここしかない
- **目標応募25本**（倍率4.2倍）

### 応募が少なかった場合／落選が多い場合

上映枠が6本しかないため、**「全作品上映に切り替える」逃げは使えない**。代わりに：

- **「入選」を作る。**上映6本とは別に、**入選作品10本程度をサイト・パンフに作品名／監督名／スチール付きで掲載する。**
  上映されなくても公式に名前が残る＝実績になる。コストはほぼゼロで、リピート率（第一指標）に直接効く
- 全応募者への講評は既定どおり必ず送る
- 応募が8本を下回った場合のみ、審査を「セレクション」と呼び替え、落選という語を使わない

**枠2：九州の映像作家**（ここが最も重要で、最も難しい）

## 11. 決定：応募フォームは yolo-tickets に相乗りする（Googleフォームは使わない）

ラストコールで動いている**チケット予約システム `yolo-tickets`**（Next.js + Drizzle + Neon + Resend）を
共通基盤として使う。README にも「今後の天草上映・**映画祭**でも再利用する共通基盤」と書いてある。
設計の詳細は `ENTRY-FORM-SPEC.md` §0。

### なぜGoogleフォームをやめるか

いちばん大きいのは**Googleログインの強制**。Googleフォームでファイルを受け取ろうとすると
回答者にログインを強制するため、ENTRY-FORM-SPEC は苦肉の策で「本編もスチールも共有URLで提出」に
していた。自前なら受け取り方を自由に決められる。

加えて、Googleフォームだと**受付番号の手動採番**と**審査進行のスプレッドシート管理**が残る。
第2回は「全応募者に講評を返す」が第一指標に直結する運用なので、
**応募・ステータス・講評送信が1画面で完結する**ことの価値が大きい。

### 実装のかたち

既存の予約テーブルをなぞる：`reservations` → **`submissions`**、
`reservationCode`（`LC-4F7K2M`）→ `entryCode`（`YTFF2-001`・自動採番）、
`manageToken`（予約の変更・キャンセル）→ **締切まで応募内容を差し替えられるリンク**。
QR／チェックインは応募では使わない。スタッフ画面は応募一覧・形式チェック・審査ステータス・講評送信に置き換える。

**副産物：11月のチケット予約がタダで手に入る。** `denkikan-20261212` を seed するだけで、
12/12 の予約・QR受付・当日ダッシュボードがそのまま動く。応募と予約が同じ基盤に乗る。

### 見積もり

7/28〜8/2。Googleフォーム（1〜2時間）より確実に重いが、**11月のチケット構築が消える**ので
第2回トータルでは得。ここが唯一の残ブロッカー。

## 12. 決定：実写／AI の部門判定は「画がどこから来たか」だけで決める

これまでの「AIを**主要な工程**に使ったか」という書き方は、応募者が自己判断できない。
「主要」の解釈が人によってぶれるし、判断に迷うこと自体が応募をやめる理由になる。
恒久ルールとして MASTER-PLAN §2 に明文化した。

| 状況 | 部門 |
|---|---|
| 本編尺のうち **AI生成の映像が50%以上** | **AI部門** |
| 50%未満 | **実写部門** |
| 脚本・音楽・音声合成・色調整・ノイズ除去にAIを使ったが、画はカメラ由来 | **実写部門** |
| ちょうど半々でどちらとも言える | **応募者が選ぶ**（選んだ部門で審査。後から変更しない） |

- 事務局の一次チェックで明らかな不一致（AI生成9割なのに実写部門）を見つけたら**部門移動を提案する**。
  **部門違いを理由に落とさない**（形式で落とさないのは MASTER-PLAN §4 の一次審査の原則どおり）
- 審査基準は両部門とも同じ（物語40／まちらしさ30／技術・表現30）
- 上映6本のうち**2本をAI部門に確保**（§4）

### AI利用の申告は両部門とも必須にする

ENTRY-FORM-SPEC は当初、AI申告をAI部門の応募者だけに聞く設計だった。**これは穴。**
実写部門にも背景生成・音声合成・アップスケールなどでAI素材が紛れ込む可能性があり、
そこを聞かないと権利リスク（§5）を拾えない。

- まず全員に「生成AIを使いましたか（はい／いいえ）」を聞く
- 「はい」の人にだけツール名・工程・**AI生成映像の割合**・権利状況を聞く
- 割合の回答は**部門判定の裏取り**に使う（自己申告した部門と食い違えば事務局から連絡）
- 申告欄には毎回「**申告による不利益はありません**」と明記する。
  正直に書いた人が損をする設計にすると、誰も書かなくなる
